## 3. Conditions applied

| Source | Condition | Applied |
|---|---|---|
| Mobile 1, security 2, QA 5 | A key store that cannot be read must not delete the session or create a new key | `session-storage.ts`: the key is read outside the decryption `try`; a read failure is thrown and nothing is deleted; a key is created only on write, after a successful read found none. The blob is removed only when decryption fails with a key that was read, or the store was read and holds no key. Two new SEC-03-T02 cases. |
| Security 1, privacy 1 | The email-send limit reveals invited addresses inside the app | `requestCode` reports `over_email_send_rate_limit` as sent. New REQ-ACC-01c-T02 case: two requests in a row give the same results for an invited and an uninvited address. Server side deferred (section 4). |
| Security 1(b), QA 11 | Do not overclaim REQ-ACC-01b and 01c | Test names say "app side". REQ-ACC-01b-T02 and REQ-ACC-01c-T02 do not satisfy their requirements; the integration tests T01 remain required. |
| Mobile 2, security 5 | Lint rule must block the client module, `require()`, `import()` and new folders | Rule applies to every source file except `src/data/**`, `__tests__/**` and `eslint.config.js`; blocks `@supabase/*` and `**/data/client` by import, `require()` and `import()`.
